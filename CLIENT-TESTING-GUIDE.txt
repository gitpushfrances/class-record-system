PURPOSE

  - Mark each step:  [P] passed   [F] failed   [S] skipped

-------------------------------------------------------------------------------
 PART 0. INSTALL OR UPDATE THE SYSTEM
-------------------------------------------------------------------------------

REQUIREMENTS (Windows)
  - XAMPP with PHP 8.1 or newer (tested on PHP 8.4) and MySQL, installed in
    C:\xampp  (backups only work from this folder in this version)
  - In C:\xampp\php\php.ini these lines must NOT start with ";" :
        extension=zip
        extension=gd
    Restart Apache after editing.
  - Composer 2, Node.js 18 or newer, Git (Git Bash)
  - Access to the GitHub repository (ask the developer to add your GitHub
    account if the repository is private)

FIRST-TIME INSTALL (Git Bash)
  1. Start Apache and MySQL in the XAMPP Control Panel.
  2. Open phpMyAdmin (http://localhost/phpmyadmin) and create an empty
     database named:  class_record
  3. Run, one line at a time:

     cd ~/Desktop
     git clone https://github.com/gitpushfrances/class-record-system.git
     cd class-record-system
     git checkout v1.0-rc1
     composer install
     npm ci
     npm run build
     cp .env.example .env
     php artisan key:generate

  4. Open the file .env in a text editor and set:
        DB_DATABASE=class_record
        DB_USERNAME=root
        DB_PASSWORD=          (leave empty if your MySQL root has no password)
  5. Run:

     php artisan migrate:fresh --seed
     php artisan storage:link
     php artisan serve

  6. Open http://127.0.0.1:8000 in the browser. Keep the Git Bash window open
     while testing (closing it stops the system).

UPDATE TO A NEW TEST VERSION (when the developer sends a new version name,
for example v1.0-rc2)

     cd ~/Desktop/class-record-system
     git fetch --tags
     git checkout v1.0-rc2
     composer install
     npm ci
     npm run build
     php artisan migrate
     php artisan optimize:clear
     php artisan serve

START AGAIN WITH CLEAN SAMPLE DATA (erases everything in class_record)

     php artisan migrate:fresh --seed

 PART 1. SIGN-IN AND ACCOUNTS (everyone)
-------------------------------------------------------------------------------

1.1  Open http://127.0.0.1:8000
     EXPECTED: green ESSU sign-in page with the letterhead and "Sign In".

1.2  Sign in with admin@classrecord.test and a WRONG password.
     EXPECTED: error message; you stay on the sign-in page.

1.3  Enter a wrong password 5 or more times quickly.
     EXPECTED: "Too many login attempts" with a waiting time.
     (Wait it out before continuing.)

1.4  Sign in as pending@classrecord.test / password.
     EXPECTED: not allowed in; "Your account is pending approval. Please wait
     for admin/dean approval."

1.5  On the sign-in page, open the request-account page and register a new
     account: your own test name, an email such as newteacher@test.com and a
     password.
     EXPECTED: message that the request was submitted and must be approved.
     Signing in with it is refused until the Admin approves it (step 2.4).

1.6  Sign in as each sample account once, then click Logout.
     EXPECTED: each lands on its own dashboard (Admin, Dean, Program Head,
     Teacher). After Logout, the browser Back button does not show the
     dashboard again.

1.7  Any role: open Profile (bottom of the sidebar). Change the name, save.
     EXPECTED: saved message; the new name appears in the sidebar.

 PART 5. TEACHER - GRADES  (teacher@classrecord.test)
-------------------------------------------------------------------------------

5.1  Dashboard, My Advisory, My Subjects open.
     EXPECTED: My Advisory shows BSCS 3-A (male and female groups);
     My Subjects shows CS301.

5.2  Open CS301 -> Grade Config.
     For a short test, set the weights like this (others 0):
       Midterm: Quiz 40, Exam 40, Attendance 20        (total 100)
       Finals:  Final Exam 40, Final Project 40, Attendance (F) 20 (total 100)
     Pick the computation method (standard table, major formula, or minor
     formula), Save Configuration.
     EXPECTED: saved. A total other than 100 per period is refused.

5.3  Class Record -> "+ Add" on Quiz (date, highest possible score 20).
     Type scores in the cells. Add one Exam, one Final Exam and one Final
     Project item the same way.
     EXPECTED: names are given automatically (Quiz 1, Midterm Examination...);
     totals and grades update after each cell; a blank cell clears the score.

5.4  Attendance ("+ Take"):
       - one date ON or BEFORE the midterm cutoff (Lecture and Laboratory)
       - one date AFTER the midterm cutoff (Lecture and Laboratory)
     Use All Present / All Absent, then Save Attendance.
     EXPECTED: saved; View Summary shows the rates. Marking a student absent
     3 times in a row shows an absence warning.

5.5  Students (per-subject class list): search and Add one of the students
     imported in 3.3 (not in the section, so added as irregular), Drop one
     student from CS301 only, then Restore.
     EXPECTED: the drop affects CS301 only; the student stays in the section.

5.6  Final Grades
     EXPECTED: midterm, finals and final grade per student. A student with
     no score in a weighted component (or 0 total) is listed as INC.
     This INC rule is the approved behavior.

5.7  Class Record -> Export Excel and Print.
     EXPECTED: an .xlsx downloads with the same grades; Print opens a
     landscape print view without buttons or sidebar.

5.8  Final Grades -> Submit for Verification -> confirm.
     EXPECTED: submitted. Scores, attendance, + Add and the class list can no
     longer be changed (locked).

 PART 7. TERM CHANGE AND PROMOTION  (do this LAST - it closes the term)
-------------------------------------------------------------------------------

7.1  Admin -> Academic Period -> Add 2024-2025 2nd Semester -> Set Active.

7.2  Program Head -> Sections -> Set Term on BSCS 3-A while a subject is NOT
     verified.
     EXPECTED: "Subjects Not Verified" dialog listing the subject and its
     status. Cancel leaves the old term active.

7.3  Set Term again -> Close Term Anyway.
     EXPECTED: "New term started: 2nd Semester 2024-2025". The old term's
     students and grades are kept; the new term has no students yet.

7.4  Promotion (Program Head or Dean) -> BSCS -> section 3-A. The source is
     3-A's closed 1st Semester term. The target is any BSCS section with a
     term in the active period: 3-A's new 2nd Semester term (next semester)
     or a 4th-year section (create one and Set Term on it first).
     All students start UNCHECKED; tick some -> Promote selected.
     EXPECTED: ticked students are enrolled in the target section with the
     new year level; students with INC or failed grades are flagged in the
     list. NOTE: promotion cannot be undone from the screen.
